# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Foundation.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Phase 1 UI scope is narrow:** This is a refactoring and infrastructure phase, not a visual design phase.
> The existing design system is preserved exactly. The only UI work is:
> 1. Nav markup extracted to `components/nav.html` and loaded via `fetch()` — structure and behavior must be identical to current inline nav
> 2. Absolute path corrections after HTML files move from root to `pages/`
> 3. Page-specific inline `<style>` blocks migrated to `assets/css/styles.css`
>
> No new visual elements are introduced. No existing visual behavior changes.

## Nav Partial Contract

This is the primary UI deliverable of Phase 1. The nav partial must be a byte-for-byte equivalent of the current inline nav markup, re-expressed as a standalone HTML fragment.

### File Location

```
components/nav.html
```

### Required HTML Structure

The partial must contain exactly two root-level elements — the `<nav>` and the `<ul class="nav-mobile">` — with no wrapping element:

```html
<!-- ── NAV ── -->
<nav>
  <a href="/index.html" class="nav-logo"><span></span>RuutDev</a>
  <ul class="nav-links">
    <li><a href="/services.html"><span data-en="Services" data-es="Servicios">Services</span></a></li>
    <li><a href="/pricing.html"><span data-en="Pricing" data-es="Precios">Pricing</span></a></li>
    <li><a href="/pay.html"><span data-en="Pay" data-es="Pagar">Pay</span></a></li>
    <li><a href="/about.html"><span data-en="About" data-es="Nosotros">About</span></a></li>
    <li><a href="/contact.html"><span data-en="Contact" data-es="Contacto">Contact</span></a></li>
    <li><a href="/contact.html" class="nav-cta"><span data-en="Start Your Project" data-es="Comienza Tu Proyecto">Start Your Project</span></a></li>
    <div class="lang-toggle">
      <button class="lang-btn active" data-lang="en" onclick="toggleLang('en')">EN</button>
      <button class="lang-btn" data-lang="es" onclick="toggleLang('es')">ES</button>
    </div>
  </ul>
  <div class="hamburger" onclick="toggleMenu()">
    <span></span><span></span><span></span>
  </div>
</nav>
<ul class="nav-mobile" id="nav-mobile">
  <li><a href="/services.html"><span data-en="Services" data-es="Servicios">Services</span></a></li>
  <li><a href="/pricing.html"><span data-en="Pricing" data-es="Precios">Pricing</span></a></li>
  <li><a href="/pay.html"><span data-en="Pay" data-es="Pagar">Pay</span></a></li>
  <li><a href="/about.html"><span data-en="About" data-es="Nosotros">About</span></a></li>
  <li><a href="/contact.html"><span data-en="Contact" data-es="Contacto">Contact</span></a></li>
  <li><a href="/contact.html" class="nav-cta btn-primary"><span data-en="Start Your Project" data-es="Comienza Tu Proyecto">Start Your Project</span></a></li>
  <li style="padding:8px 20px;"><div class="lang-toggle"><button class="lang-btn active" data-lang="en" onclick="toggleLang('en')">EN</button><button class="lang-btn" data-lang="es" onclick="toggleLang('es')">ES</button></div></li>
</ul>
```

Path rule: All `href` values use absolute paths (e.g., `/services.html`) — not relative paths. After the folder reorganization, pages live in `pages/` but are served at root-level URLs via Vercel `cleanUrls: true` and rewrites. Absolute paths ensure the nav works from any depth. (Source: CONTEXT.md D-02, D-16; RESEARCH.md path correction analysis)

### Injection Target

Each HTML page must contain an empty `<div id="nav-placeholder"></div>` immediately after `<body>` opens, before any other content:

```html
<body>
  <div id="nav-placeholder"></div>
  <!-- page content -->
```

### Load Sequence Contract

The nav partial must be fetched and injected synchronously-equivalent before `markActiveLink()` and `applyLang()` execute. The required sequence:

1. Page loads — `<div id="nav-placeholder"></div>` is empty
2. `fetch('/components/nav.html')` is called as the first operation in `main.js`
3. Response HTML is inserted via `innerHTML` into `#nav-placeholder`
4. After injection, `markActiveLink()` is called
5. After injection, `applyLang()` is called with the current language from `localStorage`
6. All other `DOMContentLoaded` initialization runs normally

Flash-of-missing-nav prevention: The `fetch()` call must be initiated at the top of `main.js` before the `DOMContentLoaded` listener, and the nav-dependent functions (`markActiveLink`, `applyLang`) must be called inside the `.then()` callback. (Source: CONTEXT.md D-06; RESEARCH.md nav timing risk analysis)

### JS Behavior Preserved

| Behavior | Function | Contract |
|----------|----------|---------|
| Active nav link highlight | `markActiveLink()` | Must run AFTER nav injection; compares `window.location.pathname` against each `<a>` href; adds class `active` to matching link |
| Mobile hamburger toggle | `toggleMenu()` | Exposed as `window.toggleMenu` (called from `onclick` in nav HTML); toggles class `open` on `#nav-mobile` |
| Language switching | `toggleLang(lang)` | Exposed as `window.toggleLang`; updates all `[data-en]`/`[data-es]` elements including those inside the injected nav; persists to `localStorage` key `ruutdev_lang` |
| Language init on load | `applyLang()` | Must run AFTER nav injection so nav text elements get the correct language applied |
| Lang button active state | `.lang-btn.active` | The button matching the current language must carry class `active`; set by `applyLang()` after injection |

Source: CLAUDE.md JS Architecture section; CONTEXT.md D-05.

### Data Attributes in Nav

All bilingual text elements in the nav partial must carry both `data-en` and `data-es` attributes. The `applyLang()` function in `main.js` reads these attributes to swap text content. No exceptions.

| Element | data-en | data-es |
|---------|---------|---------|
| Services link | "Services" | "Servicios" |
| Pricing link | "Pricing" | "Precios" |
| Pay link | "Pay" | "Pagar" |
| About link | "About" | "Nosotros" |
| Contact link | "Contact" | "Contacto" |
| CTA link | "Start Your Project" | "Comienza Tu Proyecto" |

## Path Migration Contract

After HTML files move from root to `pages/`, all asset paths in every HTML file must be updated.

### Path Correction Rules

| Asset type | Old path (root) | New path (from pages/) |
|------------|-----------------|------------------------|
| Shared CSS | `css/styles.css` | `../assets/css/styles.css` |
| Shared JS | `js/main.js` | `../assets/js/main.js` |
| Images | `images/...` | `../assets/img/...` |
| Nav partial | n/a (inline) | `/components/nav.html` (absolute, fetched) |
| Internal page links | `about.html` | `/about` (Vercel cleanUrls) |
| Canonical meta | `https://ruutdev.com/about.html` | `https://ruutdev.com/about` |

Nav partial path is always absolute (`/components/nav.html`) regardless of page depth. (Source: CONTEXT.md D-01, D-02, D-16; RESEARCH.md path analysis)

### Files in Scope

Pages that move to `pages/`: `index.html`, `about.html`, `contact.html`, `services.html`, `pricing.html`, `pay.html`, `privacy.html`, `terms.html`

Pages that stay at root: `qualifier.html` (intentionally standalone, noindex — do not reorganize)

Source: CONTEXT.md Specifics — "qualifier.html should NOT be reorganized into pages/"

## Styles Migration Contract

Phase 1 migrates page-specific inline `<style>` blocks from each HTML file's `<head>` to `assets/css/styles.css` (or individual `assets/css/{page}.css` files).

### Rules

- All CSS rules must be migrated verbatim — no rewrites, no refactoring, no visual changes
- If a rule already exists in `css/styles.css`, do not duplicate it
- New page-specific rules go into either a dedicated page section in `assets/css/styles.css` or separate `assets/css/{page}.css` files loaded via `<link>`
- `qualifier.html` inline styles are NOT migrated — that page is self-contained by design

Source: CONTEXT.md D-07, D-08; Specifics section.
