# Plan 6: Inline Styles Migration

## Objective

Migrate all page-specific inline `<style>` blocks from each HTML page to `assets/css/styles.css`.

Purpose: STRC-03 requires no page-specific inline styles. This plan completes the CSS consolidation by moving all inline style blocks out of HTML pages and into the shared stylesheet.

Output: `assets/css/styles.css` extended with migrated page styles. All 8 HTML pages free of inline `<style>` blocks.

## Context

This plan depends on Plan 02 completing first (nav partial extracted, HTML pages already updated with nav-placeholder pattern). The HTML pages are in their final nav-refactored state and can now have their inline styles cleanly extracted.

Key constraints (from CONTEXT.md):
- D-07: Page-specific inline styles migrate to `assets/css/styles.css`
- D-08: Preserve all existing visual behavior — migration only, no redesign

**qualifier.html is explicitly excluded** — it stays self-contained with its own inline styles (CONTEXT.md Specifics).

---

## Tasks

### Task 1: Migrate page-specific inline `<style>` blocks to `assets/css/styles.css`

**Files:**
- `assets/css/styles.css` (modified — styles appended)
- `index.html` (modified — inline styles removed)
- `pages/about.html` (modified — inline styles removed)
- `pages/contact.html` (modified)
- `pages/pay.html` (modified)
- `pages/pricing.html` (modified)
- `pages/privacy.html` (modified)
- `pages/services.html` (modified)
- `pages/terms.html` (modified)

**Action:**

For EACH HTML file in `pages/` and `index.html`:

1. **Read the file** and locate any `<style>` blocks in the `<head>` section.

2. **Extract each `<style>` block's CSS content** (not the `<style>` tags themselves).

3. **Check if the rules already exist in `assets/css/styles.css`** — do not duplicate rules that are already there.

4. **Append new (non-duplicate) rules to `assets/css/styles.css`** under a clearly labeled section comment:
   ```css
   /* ═══════════════════════════════════════════════════════════════
      {PAGE NAME} — page-specific styles (migrated from inline)
   ═══════════════════════════════════════════════════════════════ */
   ```
   Use the same section banner style already established in `assets/css/styles.css` (ASCII art `═` borders with a name label).

5. **Remove the `<style>` block from the HTML file** after migration.

6. **Do NOT touch `qualifier.html`** — it stays self-contained with its own inline styles.

Migration rules (from CONTEXT.md D-07, D-08 and UI-SPEC.md Styles Migration Contract):
- Copy CSS rules verbatim — no rewrites, no optimizations, no visual changes
- If a rule already exists in `assets/css/styles.css`, skip it (no duplication)
- After migration, verify the page still renders identically in a browser

**Verify:**
```bash
# No inline <style> blocks remain in any moved page
for f in pages/about.html pages/contact.html pages/pay.html pages/pricing.html pages/privacy.html pages/services.html pages/terms.html index.html; do
  grep -c "<style>" "$f" 2>/dev/null && echo "WARN: inline style in $f" || echo "PASS: $f clean"
done

# styles.css should be larger than before (has new rules appended)
wc -l assets/css/styles.css

# qualifier.html still has its own inline styles (untouched)
grep "<style>" qualifier.html && echo "PASS: qualifier.html has inline styles (expected)" || echo "WARN: qualifier.html styles missing"
```

**Done:** No `<style>` blocks remain in any non-qualifier HTML page. All page-specific CSS rules are in `assets/css/styles.css` under labeled section comments.
