# Plan 2: Shared Nav Partial

## Objective

Extract the duplicated nav HTML into a single `components/nav.html` partial loaded via `fetch()` and refactor `main.js` to inject nav before dependent functions run.

Purpose: Nav is currently copy-pasted into every HTML file — a one-line change requires editing 8+ files. A shared partial fixes this.

Output: `components/nav.html` partial, updated `main.js` with `initNav()`, all pages updated to use the nav placeholder pattern.

## Context

This plan depends on Plan 01 completing first (pages are in `pages/`, assets in `assets/`).

Key constraints (from CONTEXT.md):
- D-04: Nav extracted to `components/nav.html`; loaded via JS `fetch()` — no build step
- D-05: Active link detection and mobile hamburger must work after migration
- D-06: Nav loads before `markActiveLink()` and `applyLang()` run (timing critical)
- D-07: Page-specific inline styles migrate to `assets/css/styles.css`
- D-08: Preserve all existing visual behavior — migration only, no redesign

**Nav timing risk (from RESEARCH.md Pitfall 1 + 2):**
The existing `markActiveLink()` is an IIFE that queries `.nav-links a` at parse time. After refactor, nav is async. The IIFE must be converted to a named function called inside the fetch `.then()` callback. See UI-SPEC.md Load Sequence Contract for the exact required order.

**Nav partial HTML contract (from UI-SPEC.md):**
All nav `href` values use absolute paths (e.g., `/services.html` → note: with cleanUrls these resolve to `/services`). The partial must contain exactly two root elements: `<nav>` and `<ul class="nav-mobile">` — no wrapper element.

Wait — per UI-SPEC.md the nav uses `/services.html` style paths in the contract example, but per Plan 01 and RESEARCH.md, absolute clean paths like `/services` should be used since cleanUrls strips extensions. Use `/services`, `/pricing`, `/pay`, `/about`, `/contact` (no `.html` extension) so they match the clean URL rewrites.

### Task 2: Refactor `assets/js/main.js` — add `initNav()`, fix markActiveLink timing

**Files:**
- `assets/js/main.js` (modified)

**Action:**

Read `assets/js/main.js` (copied from `js/main.js` in Plan 01).

Make the following targeted changes:

**Change 1 — Add `initNav()` function at the TOP of the file (before `DOMContentLoaded`)**

Add this function as the first function in `main.js`, before the `DOMContentLoaded` listener:

```javascript
/* ── Nav Partial Loader ── */
function initNav() {
  const placeholder = document.getElementById('nav-placeholder');
  if (!placeholder) return;

  fetch('/components/nav.html')
    .then(r => r.text())
    .then(html => {
      placeholder.outerHTML = html;
      // Run nav-dependent functions AFTER nav is in the DOM
      markActiveNavLink();
      const saved = localStorage.getItem('ruutdev_lang') || 'en';
      applyLang(saved);
    })
    .catch(() => {
      // Nav fetch failed — log silently, page still usable
      console.warn('RuutDev: nav partial failed to load');
    });
}

// Initialize nav immediately (before DOMContentLoaded)
// This starts the fetch early to minimize flash of missing nav
initNav();
```

**Change 2 — Convert `markActiveLink` IIFE to a named function**

Find the existing `markActiveLink` IIFE (currently runs at parse time, something like):
```javascript
(function markActiveLink() {
  // ... sets active class on nav links
})();
```

Remove the IIFE wrapper and convert it to a named function declaration that does NOT self-invoke:
```javascript
function markActiveNavLink() {
  const path = window.location.pathname;
  document.querySelectorAll('.nav-links a, #nav-mobile a').forEach(link => {
    link.classList.remove('active');
    const href = link.getAttribute('href');
    if (href && (path === href || path.startsWith(href + '/') || (href !== '/' && path.includes(href)))) {
      link.classList.add('active');
    }
  });
}
```

Important: The exact logic of the existing IIFE must be preserved. Read the current implementation and use it — only remove the self-invocation `()` at the end and rename to `markActiveNavLink`. Do not rewrite the logic.

**Change 3 — Guard the `DOMContentLoaded` `applyLang` call**

In the `DOMContentLoaded` listener, find where `applyLang()` is first called with the saved language. Ensure it runs only if nav items exist OR is safe to call idempotently. Since `applyLang` is idempotent (applying it twice does no harm), leaving the `DOMContentLoaded` call as a fallback is acceptable. No change needed here if `applyLang` already runs in `DOMContentLoaded`.

**No other changes to `main.js`** — all other functions (`toggleMenu`, `applyLang`, `toggleLang`, `initStripeReadyCtas`, `initContactPrefill`, `submitContactForm`, scroll reveal observer, FAQ accordion) remain exactly as-is.

**Verify:**

**Done:** `assets/js/main.js` has `initNav()` function, `markActiveNavLink()` as a named function (not IIFE), `initNav()` called at module level before `DOMContentLoaded`.

## Threat Model (ASVS L1)

### Assets Being Protected
- Nav injection point (`#nav-placeholder`) cannot be used to inject malicious HTML
- Inline event handlers (`onclick="toggleMenu()"`) are controlled by the nav partial from the same origin

### Threats

| Threat | STRIDE | Component | Severity | Disposition | Mitigation |
|--------|--------|-----------|----------|-------------|------------|
| Nav partial fetch from attacker-controlled URL | Spoofing | initNav() fetch call | Low | Accept | `fetch('/components/nav.html')` is a root-relative path to the same origin — cannot be overridden by an attacker without already having code execution |
| innerHTML injection via nav partial response | Tampering | `placeholder.outerHTML = html` in initNav() | Medium | Accept | The nav partial is a static file served from the same Vercel deploy. An attacker would need to compromise the deploy to modify it. No user input enters the nav. ASVS L1 does not require origin isolation for same-origin static assets. |
| markActiveNavLink runs before nav is in DOM | Denial of Service (UX) | initNav() timing | Low | Mitigate | markActiveNavLink called only inside `.then()` callback after `outerHTML = html` — guaranteed post-injection |
| Missing data-en/data-es on nav elements | Tampering | components/nav.html | Low | Mitigate | All nav text elements verified to have data-en and data-es in Task 1 verify step |

### Controls
- Nav fetch uses root-relative path (`/components/nav.html`) — same-origin only
- `markActiveNavLink()` and `applyLang()` called inside `.then()` callback only — prevents acting on empty DOM
- `qualifier.html` is explicitly excluded from nav extraction
</threat_model>
