# Plan 3: Contact Form Proxy + Supabase Client Utility

## Objective

Create `api/contact.js` as a serverless proxy that receives contact form submissions and forwards them to Web3Forms using a server-side API key, then update `main.js` to call the proxy instead of Web3Forms directly. Also create `api/_supabase.js` as the shared Supabase client utility that all Phase 2+ API functions will import.

Purpose: The Web3Forms API key currently lives in `js/main.js` — visible to anyone who views source. Moving it to a serverless env var satisfies STRC-04. The `_supabase.js` utility must exist before Plan 05 provisions the database, so Phase 2 API functions can immediately import it.

Output: `api/contact.js`, `api/_supabase.js`, updated `main.js`, `.gitignore` with `.env*` excluded, `.env.local` scaffold.

## Context

This plan depends on Plan 01 completing (directory structure, assets moved, `assets/js/main.js` exists). It does NOT depend on Plan 02 (nav partial) — they run in Wave 2 in parallel.

Key constraints (from CONTEXT.md):
- D-09: Web3Forms key moves out of `main.js` → `api/contact.js` proxy
- D-10: Public pages call `api/contact.js` instead of Web3Forms directly
- D-11: `WEB3FORMS_KEY` added to Vercel environment variables
- D-18: `api/_supabase.js` exports single initialized Supabase client using service-role key
- D-19: Supabase client is server-side ONLY — never imported in browser JS

**Critical order (from RESEARCH.md Pitfall 5):** The `.gitignore` entry for `.env*` must be created BEFORE the `.env.local` file is created. This prevents accidental secret commit.

**Contact form response contract:** The existing `submitContactForm()` in `main.js` checks `if (res.ok)` on the fetch response and then shows the success/error UI. The proxy must return:
- `200` + any body when Web3Forms succeeds
- Non-2xx when Web3Forms fails or request is invalid

The exact response body does not matter to the client — only the HTTP status code does (since `main.js` uses `res.ok`). The proxy pattern in RESEARCH.md Pattern 3 uses `{ success: true }` for consistency.

### Task 2: Create `api/contact.js` — Web3Forms proxy function

**Files:**
- `api/contact.js` (created)

**Action:**

Create the `api/` directory if it does not exist:
```bash
mkdir -p api
```

Create `api/contact.js` with the following implementation (based on RESEARCH.md Pattern 3). This is a Vercel serverless function using ES module syntax (required for `"type": "module"` in package.json — see Plan 04):

```javascript
// api/contact.js — Web3Forms proxy
// Receives contact form POSTs from ruutdev.com, forwards to Web3Forms
// server-side using WEB3FORMS_KEY from env vars.
// SECURITY: API key never exposed to client-side JS.

export default async function handler(req, res) {
  // Handle CORS preflight
  if (req.method === 'OPTIONS') {
    res.setHeader('Access-Control-Allow-Origin', 'https://ruutdev.com');
    res.setHeader('Access-Control-Allow-Methods', 'POST, OPTIONS');
    res.setHeader('Access-Control-Allow-Headers', 'Content-Type');
    return res.status(200).end();
  }

  if (req.method !== 'POST') {
    return res.status(405).json({ error: 'Method not allowed' });
  }

  const { name, email, business, type, message } = req.body || {};

  // Basic field validation — mirrors client-side validation in main.js
  if (!name || !email) {
    return res.status(400).json({ error: 'name and email are required' });
  }

  const controller = new AbortController();
  const timeout = setTimeout(() => controller.abort(), 8000);

  try {
    const response = await fetch('https://api.web3forms.com/submit', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Accept': 'application/json'
      },
      signal: controller.signal,
      body: JSON.stringify({
        access_key: process.env.WEB3FORMS_KEY,
        name,
        email,
        business: business || '',
        type: type || '',
        message: message || ''
      })
    });
    clearTimeout(timeout);

    if (response.ok) {
      return res.status(200).json({ success: true });
    }
    return res.status(502).json({ error: 'Upstream error' });
  } catch (err) {
    clearTimeout(timeout);
    if (err.name === 'AbortError') {
      return res.status(504).json({ error: 'Request timeout' });
    }
    return res.status(500).json({ error: 'Request failed' });
  }
}
```

**Verify:**

**Done:** `api/contact.js` exists, uses `export default`, references `process.env.WEB3FORMS_KEY`, and does not contain any hardcoded secret value.

### Task 3: Create `api/_supabase.js` — shared Supabase client utility

**Files:**
- `api/_supabase.js` (created)

**Action:**

Create `api/_supabase.js` (the underscore prefix means Vercel does NOT expose this as an HTTP route — it is a utility module only):

```javascript
// api/_supabase.js — Shared Supabase client for serverless functions
// SERVER-SIDE ONLY — never imported by browser JS (no browser bundle)
// Uses service-role key which bypasses RLS — only safe in serverless context.
// For public READ operations in Phase 2, consider using SUPABASE_ANON_KEY instead.

import { createClient } from '@supabase/supabase-js';

if (!process.env.SUPABASE_URL || !process.env.SUPABASE_SERVICE_ROLE_KEY) {
  throw new Error('SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY environment variables are required');
}

export const supabase = createClient(
  process.env.SUPABASE_URL,
  process.env.SUPABASE_SERVICE_ROLE_KEY
);
```

## Threat Model (ASVS L1)

### Assets Being Protected
- `WEB3FORMS_KEY` — API key for email delivery service; exposure allows anyone to send emails on behalf of ruutdev.com
- `SUPABASE_SERVICE_ROLE_KEY` — bypasses Row Level Security; exposure allows full database access
- Contact form endpoint — must not be a spam relay

### Threats
