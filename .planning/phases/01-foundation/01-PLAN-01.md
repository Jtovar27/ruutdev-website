# Plan 1: Codebase Reorganization + Vercel Config

## Objective

Reorganize the flat project root into a structured directory layout and configure `vercel.json` to maintain all existing public URLs via rewrites, add CORS headers to `/api/*`, and set a CSP header.

Purpose: Phase 2 and beyond require a stable `pages/`, `assets/`, `api/`, and `admin/` structure. The Vercel config must be in place before any API functions are deployed so headers are applied from the first deploy.

Output: Seven HTML files moved to `pages/`, CSS and JS moved to `assets/`, `vercel.json` with rewrites + headers, `index.html` updated in place.

## Context

The current project root has all HTML files, `css/`, and `js/` at the top level — no subdirectory organization. Phase 1 targets state: `pages/` for HTML, `assets/css/` and `assets/js/` for shared assets, `api/` for serverless functions, `admin/` as a placeholder.

Key constraints (from CONTEXT.md):
- D-01: Full reorganization into pages/, assets/, api/, admin/
- D-02: Vercel rewrites preserve existing public URLs
- D-03: `index.html` STAYS at root (Vercel's `/` entry point)
- D-16: vercel.json = cleanUrls + rewrites + CORS on /api/* + CSP
- `qualifier.html` stays at root — intentionally standalone (CONTEXT.md Specifics)
- `robots.txt` and `sitemap.xml` stay at root — SEO requirement

### Task 2: Create `vercel.json` with cleanUrls, rewrites, CORS headers, and CSP

**Files:**
- `vercel.json` (created)

**Action:**

Create `vercel.json` at the project root with the following exact content (per RESEARCH.md Pattern 6 and CONTEXT.md D-16):

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "cleanUrls": true,
  "rewrites": [
    { "source": "/about",    "destination": "/pages/about" },
    { "source": "/contact",  "destination": "/pages/contact" },
    { "source": "/pay",      "destination": "/pages/pay" },
    { "source": "/pricing",  "destination": "/pages/pricing" },
    { "source": "/privacy",  "destination": "/pages/privacy" },
    { "source": "/services", "destination": "/pages/services" },
    { "source": "/terms",    "destination": "/pages/terms" }
  ],
  "headers": [
    {
      "source": "/api/(.*)",
      "headers": [
        { "key": "Access-Control-Allow-Origin",  "value": "https://ruutdev.com" },
        { "key": "Access-Control-Allow-Methods", "value": "GET,POST,PATCH,PUT,DELETE,OPTIONS" },
        { "key": "Access-Control-Allow-Headers", "value": "Content-Type,Authorization" }
      ]
    },
    {
      "source": "/(.*)",
      "headers": [
        {
          "key": "Content-Security-Policy",
          "value": "default-src 'self'; script-src 'self' 'unsafe-inline' https://cdnjs.cloudflare.com https://fonts.googleapis.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com https://cdnjs.cloudflare.com https://fonts.gstatic.com; font-src 'self' https://fonts.gstatic.com https://cdnjs.cloudflare.com; img-src 'self' data: https:; connect-src 'self' https://api.web3forms.com; frame-ancestors 'none';"
        }
      ]
    }
  ]
}
```

**CSP notes (per RESEARCH.md Pattern 6):**
- `unsafe-inline` in `script-src` is required for existing `onclick=` attributes (`onclick="toggleMenu()"`, `onclick="toggleLang('en')"`) and inline `<script>` blocks
- `unsafe-inline` in `style-src` is required for page-specific `<style>` blocks (until STRC-03 migration is complete — handled in Plan 02)
- Google Fonts CDN origins (`fonts.googleapis.com`, `fonts.gstatic.com`) must appear in both `style-src` and `font-src`
- Font Awesome CDN (`cdnjs.cloudflare.com`) must appear in `style-src` and `font-src`
- `connect-src` includes `https://api.web3forms.com` as a transitional allowance; will be removed in Plan 03 after `api/contact.js` proxy is live

**Verify (local):**
```bash
# Validate JSON syntax
node -e "JSON.parse(require('fs').readFileSync('vercel.json', 'utf8')); console.log('PASS: valid JSON')"
# Confirm cleanUrls is true
node -e "const v = JSON.parse(require('fs').readFileSync('vercel.json', 'utf8')); console.log('cleanUrls:', v.cleanUrls)"
# Confirm 7 rewrites exist
node -e "const v = JSON.parse(require('fs').readFileSync('vercel.json', 'utf8')); console.log('rewrites count:', v.rewrites.length)"
# Confirm CORS header entry for /api/(.*)
node -e "const v = JSON.parse(require('fs').readFileSync('vercel.json', 'utf8')); const h = v.headers.find(h => h.source === '/api/(.*)'); console.log('CORS header present:', !!h)"
# Confirm CSP header entry
node -e "const v = JSON.parse(require('fs').readFileSync('vercel.json', 'utf8')); const csp = v.headers.find(h => h.source === '/(.*)'); console.log('CSP entry present:', !!csp)"
```

**Done:** `vercel.json` exists at root, passes JSON.parse, has `cleanUrls: true`, 7 rewrites, CORS headers on `/api/(.*)`, and CSP header on `/(.*)`

## Threat Model (ASVS L1)

### Assets Being Protected
- Existing page content and design (no regressions from file movement)
- Vercel CSP prevents XSS from injected content
- CORS header restricts API callers to ruutdev.com origin

### Threats

| Threat | STRIDE | Component | Severity | Disposition | Mitigation |
|--------|--------|-----------|----------|-------------|------------|
| Broken asset paths expose unstyled page | Tampering | pages/*.html path migration | Medium | Mitigate | All asset hrefs use root-relative absolute paths `/assets/...`; verified via grep check in Task 1 |
| CSP blocks Google Fonts or Font Awesome CDN | Denial of Service (self-inflicted) | vercel.json CSP header | High | Mitigate | CSP includes `https://fonts.googleapis.com`, `https://fonts.gstatic.com`, `https://cdnjs.cloudflare.com` in style-src and font-src per RESEARCH.md Pattern 6 |
| Overly permissive CORS allows cross-origin API abuse | Elevation of Privilege | vercel.json CORS header for /api/* | Medium | Mitigate | `Access-Control-Allow-Origin` set to `https://ruutdev.com` — not `*`; prevents arbitrary origins from calling API routes |
| Missing `frame-ancestors 'none'` enables clickjacking | Spoofing | CSP header | Medium | Mitigate | `frame-ancestors 'none'` included in CSP per RESEARCH.md Pattern 6 |
| Qualifier.html accidentally moved into pages/ | Tampering | File organization | Low | Mitigate | Explicit task instruction: do NOT move qualifier.html; it stays at root as a standalone page |
| Vercel `routes` key conflicts with /api auto-detection | Tampering | vercel.json | High | Mitigate | Using `rewrites` key (not deprecated `routes`); confirmed in RESEARCH.md anti-patterns |

### Controls
- Root-relative absolute paths on all asset references prevent path resolution errors after directory move
- `cleanUrls: true` + `rewrites` array maintains all existing public URLs without HTTP redirects
- CORS `Access-Control-Allow-Origin` scoped to production origin only
- CSP includes all CDN origins required by existing page assets
- `frame-ancestors 'none'` prevents clickjacking
</threat_model>
